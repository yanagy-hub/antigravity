# ディレクトリ・ファイル構成ルール

本プロジェクト（Antigravity）におけるディレクトリおよびファイルの構成ルールを定義します。

## 基本方針

本プロジェクトでは、ファイルやディレクトリの整理・検索性を高めるため、原則として **Johnny.Decimal形式（`NN_Name`）** を採用します。

* **形式**: `[2桁の数字]_[任意の名前]`
* **例**: `00_Config`, `01_Rules`, `90_System`

### 適用範囲
* `Antigravity_Doc` 配下のドキュメント管理フォルダ
* `Antigravity_Dev` 配下の主要な構造（フレームワークやツールの制約でプレフィックスを付けられない場合を除く）

## トップレベル構造

プロジェクト全体のルート（`Antigravity/`）は、**3つの主要レイヤー**によって構成されます。

```text
Antigravity/ (ルート)
│
├── 【1. 共通基盤・メタ管理レイヤー】 (ルート直下に配置)
│   ├── 00_Config/            # ワークスペース全体の設定、構成管理ファイル
│   ├── 10_Loop_Definitions/  # ループエンジニアリング・コア定義
│   └── 90_System/            # 共通スクリプト（91_Scripts/）や全域ツール
│
├── 【2. 開発レイヤー】
│   └── Antigravity_Dev/      # アプリケーションやプロダクトのソースコード・実装
│
└── 【3. ドキュメントレイヤー】
    └── Antigravity_Doc/      # プロジェクトの設計書、運用ルール、ナレッジ・ノート
```

### レイヤーごとの詳細

1. **共通基盤・メタ管理レイヤー (ルート直下)**
   * ワークスペース全体を支えるシステム、自動化スクリプト、共通定義、全体構成（`00_Config/Vault_Structure.md` 等）を配置します。
   * DevとDocのどちらにも偏らない共通資産として、ルート直下で独立して管理します。
   * **エージェント・スキル（Skill）の配置**:
     * スキルの定義ファイル (`SKILL.md`) は、エージェント自動検出用の **`.agent/skills/<スキル名>/`** 配下に配置します。
     * スキル等で実行される実際の処理コード（Python/Bash等）は、**`90_System/91_Scripts/`** 配下に配置し、`SKILL.md` から参照・呼び出す構成とします。

2. **`Antigravity_Dev/` (開発レイヤー)**
   * アプリケーションのソースコード、テスト、設定ファイルなどを格納します。
   * 言語やフレームワークが要求する標準的なディレクトリ構成がある場合は、そちらを優先しますが、最上位の機能モジュール等には `NN_Name` のプレフィックスを適用して整理することを推奨します。

3. **`Antigravity_Doc/` (ドキュメントレイヤー)**
   * プロジェクトの設計書、ルール、運用マニュアル、AIのプロンプトなどを格納します。
   * 完全な Johnny.Decimal 形式を適用します。

### Antigravity_Doc 推奨構成案

```text
Antigravity_Doc/
├── 00_Config/       # 全体設定、アーキテクチャ図、環境構築手順
├── 01_Rules/        # コーディング規約、運用ルール（本ファイル等）
├── 10_Design/       # 要件定義、UI/UXデザイン、データベース設計
├── 20_Manuals/      # ユーザーマニュアル、運用手順書
├── 50_Library/      # 外部の参考資料、ライブラリ仕様（読み取り専用）
└── 93_Temporary/    # 一時的なメモ、スクラッチファイル、検証ログ
```

## 注意事項

* **フォルダの作成・リネーム・削除**: 構造を変更した場合は、必ずプロジェクト全体のドキュメント（例: `00_Config/Vault_Structure.md` などがある場合）を更新し、整合性を保つこと。
* **波岐影響の確認**: フォルダ名が変更されると、スクリプトやAIのプロンプト内のパスが通らなくなる可能性があるため、影響範囲を必ず確認すること。
