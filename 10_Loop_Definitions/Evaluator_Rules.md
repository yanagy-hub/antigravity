# 評価器判定ルール仕様書 (Evaluator Rules)

本ドキュメントは、ループエンジニアリングにおける成果物・状態の品質評価（Evaluate）ルールおよび二重評価メカニズムを定義した仕様書です。

---

## 1. 評価器の二層構造

ループエンジニアリングでは、**決定論的評価（確定的な検証）** を最優先とし、補助的に **確率論的評価（AIによるレビュー）** を組み合わせます。

```
[成果物 / 実行結果]
       │
       ├──> 1. 決定論的評価 (Deterministic) ──> Pass/Fail (Pass時のみ次へ)
       │
       └──> 2. 確率論的評価 (Probabilistic) ──> スコア判定 (>= 閾値)
```

---

## 2. 決定論的評価ルール (Deterministic Evaluation)

決定論的評価は、客観的かつ再現可能なプログラム実行結果に基づきます。

| 評価項目 | 検証手段 | 合格基準 (Pass) | 不合格時のアクション |
| :--- | :--- | :--- | :--- |
| **構文チェック** | Linter ( flake8, eslint 等 ) | エラー数 == 0 | 構文修正プロンプトの生成 |
| **型チェック** | mypy, tsc 等 | 型エラー == 0 | 型定義の修正 |
| **単体テスト** | pytest, npm test 等 | 終了コード `exit_code == 0` | スタックトレースの抽出と解析 |
| **ビルド検証** | build コマンド | ビルド成功 | ビルドログの抽出と原因特定 |

---

## 3. 確率論的評価ルール (Probabilistic Evaluation)

確率論的評価は、コードの可読性、設計品質、または自然言語の成果物を評価する際に用います。

### 3.1 評価ルーブリック (採点基準)

| 観点 | 配点 (1-5) | 評価内容 |
| :--- | :--- | :--- |
| **正確性 (Accuracy)** | 1 - 5 | 要求仕様を満たしているか |
| **安全性 (Safety)** | 1 - 5 | エッジケースやセキュリティホールが含まれていないか |
| **保守性 (Maintainability)** | 1 - 5 | 適切な命名規則、簡潔な構造になっているか |

### 3.2 総合スコア算出式

$$\text{Total Score} = 0.5 \times \text{正確性} + 0.3 \times \text{安全性} + 0.2 \times \text{保守性}$$

- **合格閾値**: $\text{Total Score} \ge 4.0$ （または 1.0 満点換算で $\ge 0.80$）

---

## 4. 統合判定フロー

1. **ステップ 1**: 決定論的評価を実施。1つでも失敗した場合、即座に **FAILURE** と判定し修正ループへ。
2. **ステップ 2**: 決定論的評価が全件 Pass の場合のみ、確率論的評価を実施。
3. **ステップ 3**: 総合スコアが閾値以上であれば **SUCCESS** と判定しループを正常終了。
