# ディレクトリ・ファイル構成ルール

本プロジェクト（Antigravity）におけるディレクトリおよびファイルの構成ルールを定義します。

## 基本方針

本プロジェクトでは、ファイルやディレクトリの整理・検索性を高めるため、原則として **Johnny.Decimal形式（`NN_Name`）** を採用します。

* **形式**: `[2桁の数字]_[任意の名前]`
* **例**: `00_Config`, `20_Workspace`, `30_Document`, `50_Library`, `90_System`

### 適用範囲
* `30_Document` 配下のドキュメント管理フォルダ
* `20_Workspace` 配下の主要な構造（フレームワークやツールの制約でプレフィックスを付けられない場合を除く）

## トップレベル構造

プロジェクト全体のルート（`Antigravity/`）は、Johnny.Decimalに基づき目的別にレイヤー化されて構成されます。

```text
Antigravity/ (ルート)
│
├── 00_Config/            # ワークスペース全体の設定、構成管理ファイル (`Vault_Structure.md` 等)
├── 10_Loop_Definitions/  # ループエンジニアリング・コア定義・仕様書
├── 20_Workspace/         # 開発レイヤー（アプリ別の開発プロジェクト領域）
│   └── <アプリ名>/       # 各種開発アプリごとのプロジェクトフォルダ（例: JournalApp/）
├── 30_Document/          # 文章管理レイヤー（設計書、運用ルール、ナレッジ・ノート）
│   ├── 01_Rules/         # 規約・ガイドライン
│   └── 93_Temporary/     # 一時ドキュメント
├── 40_Management/        # プロジェクト・タスク管理、議事録
├── 50_Library/           # 外部の参考資料、論文、技術記事（原則AI読み取り専用）
├── 60_Assets/            # 画像、図表、デザインアセット
├── 70_Templates/         # 各種Markdownテンプレート
└── 90_System/            # システム管理、共通スクリプト (`91_Scripts/`)、一時作業領域 (`93_Temporary/`)
```

### レイヤー・ディレクトリごとのルール

1. **共通基盤・設定レイヤー (`00_Config/`, `10_Loop_Definitions/`)**
   - **`00_Config/`**: ワークスペース全体を支えるシステム設定、共通定義、全体構成（`00_Config/Vault_Structure.md`）を配置します。フォルダやファイルの作成・変更・削除時は直ちに `Vault_Structure.md` を更新すること。
   - **`10_Loop_Definitions/`**: ループ処理やエージェント動作の仕様書、評価器ルール、ガードレール定義ファイルを集約します。

2. **開発レイヤー (`20_Workspace/`)【重要規則】**
   - **各種開発内容は、必ず `20_Workspace/<アプリ名>/`（例: `20_Workspace/JournalApp/`）のようにアプリごとの専用ディレクトリを作成し、その配下にソースコード、設定、テスト等のすべての開発資産を作成・配置してください。**
   - ルート直下や `20_Workspace/` 直下に直接ファイルを散らさず、アプリ名ディレクトリ内でプロジェクトを完結させます。

3. **文章管理レイヤー (`30_Document/`)**
   - **`01_Rules/`**: プロジェクトの設計書、運用ルール、ガイドラインを管理します。
   - **`93_Temporary/`**: 一時的なメモや作業用ドキュメントを配置します。

4. **管理・資料レイヤー (`40_Management/`, `50_Library/`, `60_Assets/`, `70_Templates/`)**
   - **`40_Management/`**: タスク、ロードマップ、ミーティング議事録を管理します。
   - **`50_Library/`**: 外部から収集した文献、記事、APIリファレンス等の保管用です。**原則としてAIによる変更・削除は禁止（読み取り専用）** とします。
   - **`60_Assets/`**: MarkdownやWebアプリで参照する画像・メディア・図表データを一元管理します。
   - **`70_Templates/`**: 議事録や設計書のフォーマット（Markdownテンプレート）を管理します。

5. **システム・作業レイヤー (`90_System/`)**
   - **スクリプトの配置 (`90_System/91_Scripts/`)**: エージェントやスキル等で実行される新規コード・実行スクリプト（Python/Bash等）は、**必ず `90_System/91_Scripts/` 配下に配置** してください。
   - **一時ファイルの配置 (`90_System/93_Temporary/`)**: スクラッチコードや実行ログ、中間データは **`90_System/93_Temporary/` 配下に格納** してください。

## 運用ルール

* **フォルダの作成・リネーム・削除**: 構造を変更した場合は、直ちに `00_Config/Vault_Structure.md` を更新し、整合性を保つこと。
* **波及影響の確認**: フォルダ名や構造が変更された場合は、スクリプトやAIスキル内の参照パスへの影響を確認し、適宜置換を行うこと。
